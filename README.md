# 印刷套准复核台

接口只把印张偏差放进待处理队列。另一个进程用行锁领走一条，算出套准或套不准后再写回。页面每隔一秒看一次，直到结论出现。

领取进程把任务改为「领取中」时写入自己的领取进程名，出结论后该名作为落款保留。印刷员可在「领取落款」专页把领取中的任务改派给另一个领取名并留下改派履历；已出结论不可改派。改派后任务回到待处理并指名由新进程领取，再出结论时落款为新名。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3194 |
| 接口 | http://localhost:8194 |
| PostgreSQL | localhost:54394 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| printer | print123456 | 可送复核、可改派 |
| checker | check123456 | 只看落款与履历，不能改派 |

领取进程：`领取进程-甲`（worker-a）、`领取进程-乙`（worker-b）。领取后约 3 秒出结论，便于观察领取中并改派。

## 启动

```bash
cd projects/15-print-register-review
docker compose up --build
```

## 验收

1. printer 登录后稍等，封面-01 变成套准，内页-09 变成套不准，落款为领取进程-甲或乙。
2. 再送一条青偏差 0.5 的印张，状态先是待处理，随后变成领取中（队列与「领取落款」专页可见领取进程名），再变成套不准。
3. checker 没有送复核按钮，在「领取落款」专页也只能看落款与履历、不能改派。
4. printer 在「领取落款」专页把一条领取中的任务改派给另一个领取名：任务先回到待处理（待新进程领取），再出结论时落款为新名，且出现在改派履历中。
5. 已出结论的任务不在在途改派区，无法改派；按领取人筛选可同时筛在途与已落款。
