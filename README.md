# 印刷套准复核台

接口只把印张偏差放进待处理队列。领取进程用行锁领走一条，置为「领取中」时把自己的领取名写进落款；算出套准或套不准后写回结论，落款保留。印刷员可在「领取落款」专页把领取中的任务改派给另一领取名并记入履历；已出结论不可改派。页面每隔一秒看一次。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3194 |
| 接口 | http://localhost:3194/api |
| 接口直连 | http://localhost:8194 |
| PostgreSQL | localhost:54394 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| printer | print123456 | 可送复核、可改派 |
| checker | check123456 | 只看落款与履历，不能改派 |

## 启动

```bash
docker compose up --build
```

有两个领取进程并发抢任务（`FOR UPDATE SKIP LOCKED`）：领取进程甲、领取进程乙。领走后留约 8 秒「领取中」窗口，便于看到落款与改派。

## 领取落款规则

- 任务从待处理变为领取中的瞬间写入领取进程名（`claim_name`），出结论后该落款保留。
- 印刷员在「领取落款」专页可把**领取中**的任务改派给另一个领取名，改派写入 `reassignments` 履历，最终落款变成新名。
- **已出结论的任务不可改派**（接口返回 409）。
- 只读账号（checker）只能看落款与改派履历，调改派接口返回 403。

## 验收

1. printer 登录后稍等，封面-01 变成套准、内页-09 变成套不准；队列页「领取人」列与「领取落款」专页显示抢到它的进程名（甲或乙），结论出来后落款不变。
2. 再送一条青偏差 0.5 的印张：状态先是待处理，随后变领取中（专页在途改派区能看到领取进程名），在它出结论前把它改派给另一个领取名 → 履历出现一条记录，最终套不准且**落款为新名**。
3. 「按领取人筛选」选某个进程名：在途区与已落款列表都只剩该领取人的任务。
4. checker 登录：没有送复核按钮，进入领取落款页没有改派下拉与按钮，直接调 `POST /api/jobs/{id}/reassign` 返回 403。
5. 对已出结论的任务调改派接口返回 409「已出结论，不可改派」。
